# 低温冷却管网巡检审计（中国邮路问题）

巡检机器人必须从指定检修口出发、回到原处，且至少走过每条管段一次。本服务求解无向多重图上的**中国邮路 / 路由巡检问题**：

- 在每条管段均走一次的基础上，选出需要**额外重复**的管段集合，使所有节点度数为偶数；
- 增加总长度**最小**；
- **精确给出全部同优集合数量**（按不同边集合计数，平行管段与等长最短路造成的分解歧义已去重）；
- 按**边标识字典序**生成 `0` 优先规范位向量并确定规范集合；
- 依据全部最优集合把每条管段标为 **必重复 / 可重复 / 从不重复**；
- 为规范集合生成一条从检修口起止、逐步可核对、副本数精确吻合的闭合欧拉路线；
- **可选的重复段上限模式**（0–32 个不同管段）：在奇偶闭合且重复段数不超过上限的全部集合中重新精确最小化增程；更长但使用更少重复段的方案会胜出；返回上限、实际重复段数及相对无限制结果的增程差；合法上限下若无闭游则明确报告预算不可行。

## 约束与校验

- 2–18 个唯一 ASCII 节点（非空白可打印字符）；
- 1–32 条管段，唯一 ASCII 标识、正整数长度；
- 允许平行管段，禁止自环；
- 检修口必须是已声明节点；
- 断连、未知端点、重复标识、非法长度、不存在的检修口都会返回错误，并在页面定位到具体表/行；
- 审计失败时页面保留输入并清除旧结论。

## 算法要点（`app/solver.py`）

重复边集合是一个 T-join：重复边子图中恰为原奇度节点的节点度数为奇。

1. 全源 Dijkstra 得到奇度节点间最短路距离；
2. 奇度节点子集完美匹配 DP（O(2^k·k²)，k≤18）求最小增程；
3. 以匹配 DP 为门控，逐掩码合成“奇度锚点的一条最短路”与“剩余子问题的最优集合”的**对称差**，用整数掩码天然去重，得到**全部不同的最优 T-join**（小规模实测毫秒级）；
4. 集合按位向量（边标识序、`0` 优先）取最小者为规范集合；按边在全部最优集合中的出现情况分类；
5. Hierholzer 在扩展多重图上生成规范闭合路线，并对同边副本按经过次序编号。

### 重复段上限模式（`app/solver.py::solve_cardinality_constrained`）

限定重复段数后，最优解不再由奇度点间最短路构成（更"长"但更"薄"的集合可能唯一可行），匹配 DP 不再适用。问题变为基数约束下对边子集的精确最小化：

1. 边按标识序均分为两半（各 ≤16 条），枚举每半全部子集的 GF(2) 端点奇偶掩码、权重、基数；
2. 两半按奇偶掩码（异或等于原奇度掩码）会合，按 `(奇偶, 权重)` 聚合并以基数前缀和施加 `≤cap` 门控，两遍扫描得到精确最小增程与同优集合数（Python 大整数，任意精度）；
3. 同优组合中按边标识序的 0 优先位向量，先取最小可行左半再取最小右半，确定规范集合；
4. 每条边的同优出现次数由超集 zeta 变换（左半）与 33 位打包位槽计数（右半）求得，据此重算必重复/可重复/从不重复；
5. 不存在闭游时报告不可行，并以无权最短路 + 匹配给出可行所需的最小重复段数。

## 本地运行（无 Docker）

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
gunicorn -w 2 -b 0.0.0.0:8000 app.server:app
# 浏览器打开 http://localhost:8000
```

## Docker / Compose

```bash
# 构建并启动（宿主机端口可用 HOST_PORT 覆盖，默认 8080）
HOST_PORT=9090 docker compose up -d --build
# 健康检查
curl http://localhost:${HOST_PORT:-8080}/health
```

## 一键核对（verify 单次服务）

名为 `verify` 的服务依次执行：代码测试 → 奇度管网同优分类边界 → 欧拉管网零增程边界 → 镜像构建 → HTTP 冒烟，然后退出，以退出码报告结果。

```bash
# 方式一：编排脚本（包含构建 + 健康等待）
./scripts/verify.sh
HOST_PORT=9090 ./scripts/verify.sh

# 方式二：手动
docker compose build
docker compose up -d web            # 等待 healthy
docker compose run --rm verify      # 退出码 0 表示全部通过
```

不经过容器单独运行核对（会自行拉起临时 gunicorn）：

```bash
python -m app.verify
```

## 页面

左侧编辑节点/管段/检修口，可勾选"限定重复段上限"并填写 0–32 的上限，然后发起审计；成功后中部展示总长度、增加长度、同优集合数量、规范位向量与按颜色分类的管网图（力导向布局，平行管段分离绘制），预算模式下还显示**上限、实际重复段数与相对无限制结果的增程差**，右侧为逐步闭合路线。预算合法但不存在闭游时，保留编辑内容、清空旧结论并以醒目提示条说明至少需要的重复段数。点击图中管段或标签可高亮其在路线中的**全部经过位置**。

## API

`POST /api/audit`

```json
{
  "nodes": ["A", "B", "C", "D"],
  "edges": [
    {"id": "e1", "u": "A", "v": "B", "length": 1}
  ],
  "start": "A",
  "repeatCap": 4
}
```

`repeatCap` 可省略（关闭模式，响应语义与原有完全一致），或为 0–32 的整数。成功返回 `ok:true`、`totalLength`、`addedLength`、`optimalCount`、`canonicalVector`、
`canonicalEdges`、每边 `classification`（required/optional/never）、`route`（逐步方向与副本号）
及 `positions`（每条边在路线中的全部步序号）。预算模式额外返回 `budgetFeasible:true`、`repeatCap`、
`repeatCount`、`unconstrainedAddedLength`、`addedLengthDelta`。
合法上限但无闭游时返回 `ok:true`、`budgetFeasible:false`、`minimumRepeatCount`（不含 route 等结论字段）；
上限本身非法时返回 `ok:false` 且错误定位到 `repeatCap`。
输入校验失败返回 `ok:false`、`error`、`fields`、
`locations`（含表名与行号）。
